# Лабораторная работа №8 — PHP GET/POST. Обработка данных HTML-форм

**Тема:** приём данных от пользователя на сервере.
**Цель:** реализовать добавление записи через форму (POST) и поиск/фильтрацию через параметры адресной строки (GET) с серверной валидацией.

## Краткая теория
- **GET** — параметры в адресной строке (`search.php?q=php`), доступны в `$_GET`. Пригоден для поиска, фильтров, навигации. Не для изменения данных.
- **POST** — данные в теле запроса, доступны в `$_POST`. Используется для форм, меняющих данные (создание, редактирование).
- Обработка на сервере — **двухшаговый сценарий**: форма отправляет сама на себя (например `action="add.php"`), в начале скрипта проверяем `$_SERVER['REQUEST_METHOD'] === 'POST'`.
- **Серверная валидация** обязательна всегда — клиентскую можно отключить. Проверяем: пустые поля, длина, наличие в списках.
- `htmlspecialchars()` при обратном выводе; `trim()` убирает лишние пробелы; редирект `header('Location: ...'); exit;` после успешной обработки (паттерн PRG — Post/Redirect/Get).
- **CSRF / безопасность форм** — большая тема, продолжение в лабе 14.

## Ход работы
1. Доработайте `posts/add.php`:
   - форма отправляется методом `post` на `add.php`;
   - при POST: `trim(strip_tags($_POST['title']))` и `$_POST['content']`;
   - валидация: заголовок ≥ 3 символов, текст ≥ 20; ошибки сохраняйте в массив `$errors` и выводите рядом с полями;
   - при успехе — **добавьте запись в массив записей** (функция `addPost()`) и сделайте редирект на главную (`header('Location: /index.php'); exit;`).
   > Добавление в массив — временно! С лабы 9 запись будет вставляться в базу данных.
2. На главной добавьте форму поиска:
   ```html
   <form action="index.php" method="get">
     <input name="q" placeholder="Поиск...">
     <button>Найти</button>
   </form>
   ```
   В `index.php`: `$q = trim($_GET['q'] ?? '');` и фильтруйте записи, у которых `$q` встречается в заголовке или тексте. При пустом `$q` показывать все записи.
3. Добавьте фильтр по категории через GET-параметр `?category=study` (select на странице).
4. Проверьте: URL поиска должен быть читаемым и «закладкочным» (`index.php?q=php&category=study`).

## Самопроверка

- Почему валидация на сервере не заменяется валидацией на клиенте?
- Что не так с выводом `$_POST['title']` сразу в HTML без `htmlspecialchars`?
- Зачем редирект после успешного POST (PRG)? Что будет, если пользователь обновит страницу без него?

## Критерий «зачтено»
- Запись добавляется через POST, проходит серверную валидацию, ошибки показаны.
- После успешного добавления — редирект на главную.
- Работают поиск (`?q=`) и фильтр категории (`?category=`), фильтры «переживают» перезагрузку страницы.
- Поля форм в адресной строке не содержат «мусор» из-за неверного метода в `<form>`.
