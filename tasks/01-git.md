# Лабораторная работа №1 — Git и GitHub

**Тема:** создание репозитория учебного проекта.
**Цель:** получить личный репозиторий проекта, научиться базовому циклу работы с Git и оформить README.

## Краткая теория
- **Git** — система контроля версий: хранит историю изменений, позволяет откатываться и работать командой.
- **Репозиторий** — хранилище проекта (локальное на вашем компьютере и удалённое на GitHub).
- Основные команды: `git status` (что изменилось), `git add` (добавить в коммит), `git commit` (зафиксировать), `git push` (отправить на GitHub), `git pull` (забрать изменения), `git log` (история).
- **SSH vs HTTPS:** для pull можно использовать https, для push — либо токен (HTTPS), либо SSH-ключ. SSH удобнее: один раз настроить и забыть.
- **Тег** — метка на конкретный коммит: `git tag lab-01`.

## Ход работы
1. Если нет аккаунта — зарегистрируйтесь на GitHub.
2. Настройте git, если ещё не настроен:
   ```bash
   git config --global user.name "Ваше Имя"
   git config --global user.email "you@example.com"
   ```
3. На странице этого шаблона нажмите **Use this template** → создайте **свой** репозиторий `diary-blog` (без флагов README — он уже есть в шаблоне).
4. Склонируйте свой репозиторий:
   ```bash
   git clone https://github.com/<ваш-login>/diary-blog.git
   cd diary-blog
   ```
5. Оформите `README.md`: название блога, автор (вы), краткое описание проекта и цель блога.
6. Выполните первый коммит и отправку:
   ```bash
   git status          # посмотрите, что изменилось
   git add .
   git commit -m "[lab-01] Репозиторий создан, README оформлен"
   git push
   ```
7. Проверьте историю: `git log --oneline`, потом пометьте этап тегом:
   ```bash
   git tag lab-01
   git push --tags
   ```

## Самопроверка
- Что делает `git status` и зачем он перед коммитом?
- Чем отличается `git clone` от `git init`?
- Зачем нужны теги? Когда вы воспользуетесь `git checkout lab-01`?
- Что будет, если сделать коммит без `git add`?

## Критерий «зачтено»
- На GitHub существует **ваш** репозиторий `diary-blog` с README, в котором имя автора и описание проекта.
- В истории не менее одного коммита `[lab-01]` и тег `lab-01`.

## Ожидаемый результат в git
```bash
git add && git commit -m "[lab-01] ..." && git push
git tag lab-01 && git push --tags
```
