# Лабораторная работа №4 — JavaScript. Данные, переменные, функции, условия

**Тема:** работа с данными записей на клиенте.
**Цель:** хранить записи блога в структуре данных JavaScript и выводить их функциями с применением условий.

## Краткая теория
- Переменные: `let` (изменяемая), `const` (неизменяемая).
- **Массив объектов** — естественная модель записей:
  ```js
  const posts = [
    { id: 1, title: '...', content: '...', category: 'study', date: '2026-09-01' },
  ];
  ```
- **Функции** — именованные (`function f() {}`) и стрелочные (`const f = () => {}`).
- **Условия** `if / else`, сравнения; методы массива: `.filter()`, `.sort()`, `.map()`, `.forEach()`.

## Ход работы
1. В `js/main.js` создайте массив `posts` минимум с **5 записями** (свои темы; поля: `title`, `content` (2–3 предложения), `category`, `date`, `author`).
2. Напишите функцию `renderPosts(list)` — формирует разметку записей (строку) и вставляет её в `<section>` на странице (пока простейший способ — `innerHTML`).
3. Вызовите `renderPosts(posts)` при загрузке; подключите `js/main.js` в `index.html`.
4. Напишите функцию `sortPostsByDate(list)` — сортирует по дате (новые сверху) и выводит результат.
5. Напишите функцию фильтрации по категории: `filterByCategory(list, category)` и выведите записи только одной категории через условие.
6. Добавьте в подвал актуальный год из объекта `Date` (заготовка уже есть).

## Самопроверка
- Чем `let` отличается от `const` и когда какой использовать?
- Что вернёт `filter` без подходящих элементов — почему важно обработать пустой список?
- Почему записи удобно хранить списком объектов, а не отдельными переменными?
- Что делает метод `.sort()` по умолчанию и почему для дат он неподходит без аргумента?

## Критерий «зачтено»
- Массив из 5 собственных записей; вывод на страницу через функцию.
- Есть функции сортировки и фильтрации, они действительно меняют вывод.
- При отсутствии подходящих записей выводится сообщение («Ничего не найдено»).
