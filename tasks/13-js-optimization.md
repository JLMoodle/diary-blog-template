# Лабораторная работа №13 — Оптимизация JavaScript и работа интерфейса

**Тема:** делаем клиентскую часть быстрее и отзывчивее.
**Цель:** переработать JavaScript: меньше обращений к DOM, меньше лишних событий, асинхронная загрузка без блокировок.

## Краткая теория
- **Делегирование событий:** один `addEventListener` на общем родителе вместо N обработчиков на каждой карточке. Событие «всплывает» от потомка к родителю — фильтруем по `event.target.closest('.card')`.
- **Debounce:** поиск по мере ввода (`input`) дешёл — обработчик срабатывает раз в 300 мс после паузы, а не на каждое нажатие клавиши.
- **Минимум DOM-операций:** построение разметки фрагментом через `DocumentFragment` или строкой + один `innerHTML` вместо создания элемента в цикле.
- **Загрузка скриптов:** `defer` — скрипт не блокирует парсинг; атрибуты `loading="lazy"` у картинок.
- **localStorage-кеш:** повторные данные (например, список категорий) можно хранить и не запрашивать заново.

## Ход работы
1. Переведите обработчики с «в лоб» на делегирование: клики по кнопкам на карточках записей — один обработчик на контейнере списка.
2. Реализуйте живой поиск (рекомендация): поле `input` на главной фильтрует уже загруженные записи по заголовку/тексту. Оберните обработчик в `debounce(fn, 300)`.
3. Соберите вывод списка записей с использованием `DocumentFragment` (или построение строки и один `innerHTML`), чтобы при 20 записях не было сотни перерисовок.
4. Убедитесь, что `main.js` подключён с `defer`; все внешние ресурсы — асинхронно/лениво загрузка картинок.
5. Добавьте кеш: список категорий (или версия данных) храните в `localStorage` со временем жизни (например, 5 минут), чтобы не дёргать сервер при каждом входе.
6. Проверьте производительность: панель Performance/каждая функция; отметьте в README, где убраны лишние операции.

## Самопроверка

- Чем `input` без debounce опасен (на сколько запросов/перерисовок)?
- Почему поочерёдный `append` в цикле медленнее одного `DocumentFragment`?
- Что делает `defer` и чем он отличается от отсутствия атрибута?

## Критерий «зачтено»
- Список и его кнопки работают через один общий обработчик.
- Живой поиск с debounce действительно ощущается быстрее (замер/визуально).
- Рендер списка — фрагментом, `main.js` — с `defer`.
- Вывод о результатах оптимизации добавлен в README.
