# Лабораторная работа №12 — Оптимизация SQL-запросов и PHP-обработки

**Тема:** делаем БД и обработку быстрее и аккуратнее.
**Цель:** измерить, каким образом запросы работают, ускорить частые операции (список, поиск, категории) и убрать неэффективности в PHP.

## Краткая теория
- `EXPLAIN SELECT ...` показывает, как MySQL исполняет запрос, какие индексы используются, сколько строк перебирается.
- **JOIN** объединяет таблицы: `posts JOIN categories ON ...` — одна хорошая выборка вместо N запросов в цикле (проблема N+1).
- **Индексы** ускоряют WHERE/JOIN/ORDER BY. Функции в условии (`WHERE DATE(created_at) = ...`) ломают использование индекса.
- **Пагинация**: `LIMIT 10 OFFSET 20` вместо бесконечной выгрузки всех записей.
- Профилирование PHP: `microtime(true)` до/после, вывод времени в консоль/лог. Измерить — значит улучшать целенаправленно.
- Prepared statements готовятся один раз и переиспользуются; параметры не разбираются как код.

## Ход работы
1. Уберите проблему N+1: список записей на главной и в `posts/index.php` выводите категорию и автора **одним JOIN-запросом**, а не повторными запросами в цикле.
2. Проверьте `EXPLAIN` для главной выборки и фильтра по категории. Добейтесь, чтобы использовался индекс (`type = ref` / `range`, key = `idx_posts_category`), а не `ALL` (полное сканирование).
3. Замените поиск из лабы 8: обычный `LIKE '%q%'` перебирает все строки. Как вариант — `MATCH(title, content) AGAINST (? IN NATURAL LANGUAGE MODE)` по FULLTEXT-индексу (см. `schema.sql`), с ограничением по статусу и пагинацией.
4. Добавьте пагинацию на главную: `LIMIT/OFFSET` по 5 записей на страницу, ссылки «1 2 3 …», параметр `?page=`. Сохраняйте параметры поиска при переходе по страницам.
5. Оптимизируйте PHP:
   - вынесите повторяющийся код выборок категорий/записей в функции `includes/functions.php`;
   - кешируйте категории в одной переменной (список создаётся один раз);
   - выводите только те записи, что реально видны (не fetchAll всей таблицы при пагинации: используйте `fetchAll()` на подмножестве либо `LIMIT`).
6. Замерьте время главной до и после (микроскрипт в консоли или заголовок `X-Time`). Результаты замеров и выводы оформите в `README.md` (секция «Оптимизация, лаба 12»).
