# Лабораторная работа №8 — PHP: GET и POST. Обработка HTML-форм на сервере

## Как работать в этой лабе (общий репозиторий группы)

В этой папке `lab-08-get-post/` вы создаёте свою подпапку по фамилии и ведёте код только в ней.

1. Перед началом работы забрать чужие правки: `git pull --rebase`.
2. Создать свою подпапку: `mkdir lab-08-get-post/<Фамилия>` (латиницей, например `kimsan`).
3. Скопировать скелет лабы **целой папкой** в свою подпапку, чтобы не сломались
   относительные пути (`css/`, `js/`, `data/`, `includes/`).
4. Правите только своё; чужие подпапки и скелеты не трогайте.
5. Сдача лабы — см. раздел «Как отправить» в конце этого файла.


**Цель:** принимать данные с формы через `POST`, валидировать на сервере, выдавать ответ
через `GET`; понять, когда какой метод уместен, и уметь различать «параметры запроса»
от «тела запроса». Результат — страницы «добавить запись» и «поиск записей».

## Что нужно реализовать (чек-лист)

- [ ] `posts/add.php` — форма записи, отправляется методом `POST` **на саму себя**
      (`action=""`), обработка и вывод — в одном файле.
- [ ] Серверная валидация: заголовок ≥ 3 символов, текст ≥ 20, выбранная категория из
      белого списка. Ошибки возвращаются в форму и показываются над полями.
- [ ] При успехе — запись добавляется в массив и выполняется **редирект**
      (`header('Location: index.php')`), чтобы повторное обновление страницы не создавало дубль
      (принцип PRG).
- [ ] `index.php` — «поиск» через `GET`: поле в форме `method="get"`, в PHP —
      `$_GET['q']`, результат — отфильтрованный список + сохранённое значение в поле ввода.
- [ ] Всё, что приходит от пользователя и попадает на страницу, выводится через `e()`.
- [ ] Форма заполнения/поиска показывает предыдущие значения после ошибки/поиска.

## Краткое объяснение (теория + документация)

- **GET** — параметры в адресной строке (`?q=php`), видимые и «закладочные». Годится для
  поиска, фильтров, навигации — для **получения**. https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods/GET
- **POST** — данные в теле запроса, не «светятся» в адресной строке. Для изменения состояния
  (создание записи). https://developer.mozilla.org/en-US/docs/Web/HTTP/Methods/POST
- **Где лежат данные в PHP:** `$_GET` (параметры после `?`), `$_POST` (тело запроса),
  `$_REQUEST` (объединение — для курса используем явные `$_GET`/`$_POST`, чтобы код был
  предсказуемым). https://www.php.net/manual/ru/reserved.variables.php
- **Доступ к значению с безопасным значением «по умолчанию»:**
  `$q = $_GET['q'] ?? '';` — оператор объединения с NULL `??`.
- **Редирект (PRG — Post/Redirect/Get):** после успешной обработки POST сервер отвечает
  редиректом `Location`, и браузер повторным GET запрашивает страницу. Без этого обновление
  (F5) повторно отправит тот же POST и создаст дубликат.
- **Вывод:** ни одно пользовательское значение (включая «свои» записи) не выводится без `e()`
  (лаба 7). Мы применяем его сразу, чтобы не собирать потом «долг безопасности» (лаба 14).

## Пошаговая инструкция

1. Возьмите из лабы 7 `includes/` (header/footer/functions). В `functions.php` функция
   `getPosts()` уже возвращает массив записей.
2. Создайте `posts/add.php`:
   - в начале файла `require ../includes/functions.php`;
   - объявите `$errors = []`, `$old = [...]` (значения для формы);
   - `if ($_SERVER['REQUEST_METHOD'] === 'POST') { ... }` — внутри валидация (лаба 7 — где
     уже была такая логика, перенесите проверки полей из лаб 4–5 на сервер);
   - при ошибках — заполните `$errors` и `$old`, **не** делайте вставку;
   - при успехе — `getPosts()[] = [...]` (или временный массив), затем
     `header('Location: ../index.php'); exit;`;
   - ниже — HTML-форма с `value="<?= e($old['title'] ?? '') ?>"` и выводом
     сообщений об ошибках.
3. В `index.php` добавьте форму поиска:
   ```html
   <form action="index.php" method="get">
     <input type="text" name="q" value="<?= e($_GET['q'] ?? '') ?>">
     <button>Поиск</button>
   </form>
   ```
   и фильтр: `$q = trim($_GET['q'] ?? '');`; если `$q !== ''` — `array_filter` по
   `mb_stripos($post['title'], $q) !== false` (или по содержимому).
4. Поэкспериментируйте вручную: `index.php?q=php` — работает поиск; `posts/add.php` с
   пустым заголовком — ошибка «минимум 3 символа», данные формы сохранены.
5. Проверьте: обновление страницы после успешного добавления не создаёт дубликатов.

- В чём опасность `$_REQUEST` по сравнению с явными `$_GET`/`$_POST`?
- Зачем `exit;` после `header('Location: ...')`?

## Критерий «зачтено»

- форма `posts/add.php` обрабатывает POST и валидирует на сервере + сохраняет ввод при ошибках;
- поиск через GET фильтрует записи и возвращает значение в поле;
- PRG-редирект после успеха (нет дублей при F5);
- весь вывод — через `e()`.
