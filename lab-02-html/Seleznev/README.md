# Лабораторная работа №2 — HTML. Создание структуры клиентского приложения

## Как работать в этой лабе (общий репозиторий группы)

В этой папке `lab-02-html/` вы создаёте свою подпапку по фамилии и ведёте код только в ней.

1. Перед началом работы забрать чужие правки: `git pull --rebase`.
2. Создать свою подпапку: `mkdir lab-02-html/<Фамилия>` (латиницей, например `kimsan`).
3. Скопировать скелет лабы **целой папкой** в свою подпапку, чтобы не сломались
   относительные пути (`css/`, `js/`, `data/`, `includes/`).
4. Правите только своё; чужие подпапки и скелеты не трогайте.
5. Сдача лабы — см. раздел «Как отправить» в конце этого файла.


## Цель

Создать каркас сайта «Блог-дневник» на **семантическом HTML5**: осмысленные блоки, две
связанные страницы, собственный контент. Конечный результат — структура, к которой в
лабораторной №3 добавится оформление, а в №4–6 — логика.

## Что нужно реализовать (чек-лист)

- [ ] `index.html`: шапка `<header>` с названием и меню `<nav>` (Главная, О блоге).
- [ ] В `<main>` раздел `<section>` «Последние записи» с **не менее чем 3** записями-`<article>`.
- [ ] `about.html`: страница «О блоге» с автором и целью блога.
- [ ] Боковая колонка `<aside>` «Категории» со ссылками.
- [ ] `<footer>` с копирайтом.
- [ ] Страницы связаны ссылками в меню.
- [ ] HTML проходит проверку валидатора (validator.w3.org).

## Объяснение (мини-теория + документация)

**Семантические теги** несут *смысл*, а не только вид: `<header>` (шапка блока),
`<nav>` (навигация), `<main>` (главный контент, один на страницу), `<section>` (раздел),
`<article>` (самостоятельная единица — запись блога), `<aside>` (дополнительное содержание:
категории, ссылки), `<footer>` (подвал). Семантика важна для доступности (скринридеры),
SEO и читаемости кода — по структуре сразу видно, где что находится.

В `<head>` обязательно: `<!DOCTYPE html>`, `<html lang="ru">`, `<meta charset="UTF-8">`,
`<meta name="viewport" content="width=device-width, initial-scale=1.0">` (корректный вид на
телефонах) и `<title>`.

> **Документация:**
> Структура HTML-документа (MDN): https://developer.mozilla.org/ru/docs/Web/HTML
> Семантические элементы: https://developer.mozilla.org/en-US/docs/Glossary/Semantics
> `<article>/<section>/<aside>/<nav>/<header>/<footer>` — раздел «Документация»: https://developer.mozilla.org/en-US/docs/Web/HTML/Element
> Валидатор HTML: https://validator.w3.org/

## Пошаговая инструкция

1. Откройте в редакторе файл `index.html` из этой папки (это рабочая копия — работаем в ней,
   ничего не копируя).
2. Проверьте `<head>`: кодировка, viewport, осмысленный `<title>`.
3. Соберите шапку: `<header>` → заголовок блога `<h1>Мой дневник</h1>`, `<nav>` со ссылками
   `index.html` и `about.html`.
4. В `<main>` разместите `<section>` «Последние записи» и внутри — **свои** записи:
   - каждая запись — `<article>` с заголовком `<h2>`/`<h3>`, датой `<time datetime="...">`,
     коротким текстом и ссылкой «Читать далее»;
   - придумайте реальные темы вашего дневника (учёба, хобби, технологии…).
5. Правее контента — `<aside>` «Категории»: 3–4 ссылки-категории (например, `study`, `hobby`,
   `tech`, `life`).
6. Внизу — `<footer>`: `© 2026 Мой дневник` (год потом станет динамическим в лабе №4).
7. Создайте/дополните `about.html`: `<main>` → `<section>` «Об авторе» — пара абзацев о себе
   и о целях блога, можно с `<address>` или списком.
8. Прогоните обе страницы через https://validator.w3.org/ и исправьте замечания.
9. Откройте `index.html` в браузере: навигация работает, страницы связаны.

## Самопроверка

- Почему не стоит оборачивать всю страницу в `<div>`, если есть семантические теги?
- Чем `<article>` отличается от `<section>`? (article — самодостаточный блок, section — раздел страницы.)
- Зачем нужен `<time datetime="...">`, а не просто текстовое «1 сентября»?
- Что «сломается» без `<meta name="viewport">` на телефоне?

## Критерий «зачтено»

- Обе страницы валидны и связаны между собой ссылками в `<nav>`.
- Использованы все теги: `header, nav, main, section, article, aside, footer`.
- На главной — не менее 3 собственных записей.
- Валидатор не сообщает об ошибках (допустимы только предупреждения-«warnings»).
