# Лабораторная работа №1 — Git и GitHub. Создание репозитория учебного проекта

## Как работать в этой лабе (общий репозиторий группы)

Все студенты группы ведут проект в **одном общем репозитории**. В каждой папке
`lab-NN/` вы создаёте свою подпапку `<Фамилия>/` и работаете только в ней.

1. Склонируйте общий репозиторий группы (один раз):
   ```bash
   git clone https://github.com/JLMoodle/diary-blog-template.git
   cd diary-blog-template
   ```
2. Перед началом работы всегда забирайте чужие правки:
   `git pull --rebase`.
3. В этой лабе (и в любой следующей) создайте свою подпапку и ведите код в ней:
   ```bash
   mkdir lab-01-git/<Фамилия>
   ```
4. Не трогайте чужие подпапки и скелеты — конфликты и правила совместной работы
   разбираются в [`git-conflicts.md`](../git-conflicts.md).

## Цель

Получить **свой** репозиторий проекта «Блог-дневник», научиться базовому циклу работы с Git
(готовить, фиксировать, отправлять изменения) и оформить README. С этого момента у вас есть
рабочий инструмент на весь курс: каждая следующая лабораторная будет заканчиваться коммитом и тегом.

## Что нужно реализовать (чек-лист)

- [ ] Вы склонировали **общий репозиторий группы** и настроили `user.name`/`user.email`.
- [ ] Создали свою подпапку `lab-01-git/<Фамилия>/` и поместили туда блок «Студент».
- [ ] Сделан коммит `[lab-01]` и отправлен на GitHub (`git push`).
- [ ] Вы свободно объясняете цикл add/commit/push и назначение тегов (в общем репо
      теги ставит преподаватель как вехи курса).

## Объяснение (мини-теория + документация)

**Git** — система контроля версий. Она запоминает **историю изменений** проекта: каждый набор
правок — это коммит (снимок состояния). Удалённая копия проекта на GitHub называется
**удалённый репозиторий (remote)**.

Основной цикл «записать и отправить»:

```
изменения в файлах  →  git add (взять в коммит)
                   →  git commit (зафиксировать снимок)
                   →  git push (отправить на GitHub)
```

- `git status` — что изменилось, но ещё не закоммичено.
- `git log --oneline` — список коммитов истории.
- `git tag <имя>` — метка-закладка на конкретный коммит (`lab-01`, потом `lab-02`, …).
- `git checkout <тег>` — вернуться к состоянию проекта на момент тега.

**В этом курсе теги — вехи курса**: их ставит преподаватель (в шаблоне `lab-01…lab-15`
и `v1.0` уже стоят). Они однозначно фиксируют состояние на момент лабораторной, поэтому
проверяющему не нужно гадать, «какая версия» прислана. Студенты личные теги не ставят:
**сдача лабы = ваша подпапка `<Фамилия>/` в main**.

> **Документация:** официальная книга «Pro Git» (русский перевод): https://git-scm.com/book/ru/v2
> Основы коммитов: https://git-scm.com/book/ru/v2/Основы-Git-Запись-изменений-в-репозитории
> Теги: https://git-scm.com/book/ru/v2/Основы-Git-Работа-с-тегами
> Руководства GitHub: https://docs.github.com/ru/get-started


## Пошаговая инструкция

1. Если у вас нет учётной записи на GitHub — зарегистрируйтесь: https://github.com/signup
   (идентификатор под каждым коммитом будет виден по `user.name`/`user.email`).
2. Настройте Git один раз на вашем компьютере:
   ```bash
   git config --global user.name  "Ваше Имя"
   git config --global user.email "you@example.com"
   ```
3. Склонируйте **общий репозиторий группы** и откройте шаблон персонального блока:
   ```bash
   git clone https://github.com/JLMoodle/diary-blog-template.git
   cd diary-blog-template
   lab-01-git/my-project-readme.md   # в Windows: start ...
   ```
4. Создайте свою подпапку в этой лабе:
   ```bash
   mkdir lab-01-git/<Фамилия>
   ```
5. Заполните поля в `my-project-readme.md` (персональный блок «Студент»). Блок
   **хранится в вашей подпапке и не добавляется в корневой README** общего репозитория —
   так ваша работа остаётся персональной, а общий README не провоцирует конфликты.
6. Выполните первый учебный коммит **в своей подпапке**:
   ```bash
   git status          # что изменилось
   git add lab-01-git/<Фамилия>/
   git commit -m "[lab-01] <Фамилия>: репозиторий курса оформлен, README обновлён"
   git pull --rebase && git push
   ```
7. Изучите учебный цикл add/commit/push и назначение тегов (см. «Мини-теория» выше);
   на практике лабы сдаются **папкой в main** (см. `git-conflicts.md` в корне).
8. Убедитесь онлайн: `https://github.com/JLMoodle/diary-blog-template/tree/main/lab-01-git/<Фамилия>`
   — папка на месте, это первый «камень» вашего курса. Сдаёте: `lab-01`.

## Самопроверка

- Что делает `git status` и зачем он нужен перед коммитом?
- Чем `git clone` отличается от `git init`?
- Зачем нужны теги? Что вы увидите, выполнив `git checkout lab-01`?
- Что будет, если сделать `git commit` без предварительного `git add`?
- Где хранится ваша «папка» проекта — на компьютере или на GitHub? (Ответ: и там, и там; локальная и удалённая копии. `push` синхронизирует их.)

- Создана ваша подпапка `lab-01-git/<Фамилия>/` в main; в ней блок «Студент».

## Как отправить (протокол сдачи курса)

После каждой лабораторной отправляйте **одну строку** преподавателю:

```
Сдаю: lab-01
https://github.com/JLMoodle/diary-blog-template/tree/main/lab-01-git/<Фамилия>
```

Важно: работайте **внутри своей подпапки** (`lab-02-html/<Фамилия>/…`), не трогайте
папки других лаб и чужие подпапки — тогда ничто не перемешается между заданиями.
