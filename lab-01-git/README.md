# Лабораторная работа №1 — Git и GitHub. Создание репозитория учебного проекта

## Цель

Получить **свой** репозиторий проекта «Блог-дневник», научиться базовому циклу работы с Git
(готовить, фиксировать, отправлять изменения) и оформить README. С этого момента у вас есть
рабочий инструмент на весь курс: каждая следующая лабораторная будет заканчиваться коммитом и тегом.

## Что нужно реализовать (чек-лист)

- [ ] Личный репозиторий `diary-blog`, созданный **из этого шаблона** (кнопка *Use this template*).
- [ ] Настроены имя и e-mail в Git (`git config --global user.name/user.email`).
- [ ] Репозиторий склонирован локально (`git clone`).
- [ ] В README указаны ваши данные (блок «Студент» из шаблона `my-project-readme.md`).
- [ ] Сделан первый коммит `[lab-01] ...` и отправлен на GitHub (`git push`).
- [ ] Поставлен и отправлен тег: `git tag lab-01 && git push --tags`.
- [ ] Понимаю разницу между `git add / commit / push / pull / clone / status`.

## Объяснение (мини-теория + документация)

**Git** — система контроля версий. Она запоминает **историю изменений** проекта: каждый набор
правок — это коммит (снимок состояния). Удалённая копия проекта на GitHub называется
**удалённый репозиторий (remote)**.

Основной цикл «записать и отправить»:

```
изменения в файлах  →  git add (взять в коммит)
                   →  git commit (зафиксировать снимок)
                   →  git push (отправить на GitHub)
```

- `git status` — что изменилось, но ещё не закоммичено.
- `git log --oneline` — список коммитов истории.
- `git tag <имя>` — метка-закладка на конкретный коммит (в вашем случае `lab-01`, потом `lab-02`, …).
- `git checkout <тег>` — вернуться к состоянию проекта на момент тега.

**В этом курсе теги — инструмент сдачи**: они однозначно фиксируют состояние на момент
лабораторной, поэтому проверяющему не нужно гадать, «какая версия» прислана.

> **Документация:** официальная книга «Pro Git» (русский перевод): https://git-scm.com/book/ru/v2
> Основы коммитов: https://git-scm.com/book/ru/v2/Основы-Git-Запись-изменений-в-репозитории
> Теги: https://git-scm.com/book/ru/v2/Основы-Git-Работа-с-тегами
> Руководства GitHub: https://docs.github.com/ru/get-started

## Пошаговая инструкция

1. Если у вас нет учётной записи на GitHub — зарегистрируйтесь: https://github.com/signup
   (идентификатор под каждым коммитом будет виден по `user.name`/`user.email`).
2. Настройте Git один раз на вашем компьютере:
   ```bash
   git config --global user.name "Ваше Имя"
   git config --global user.email "you@example.com"
   ```
3. На странице **этого** репозитория нажмите зелёную кнопку **Use this template**:
   владельцем выберите себя, имя репозитория — `diary-blog` (не ставьте галочки README/.gitignore —
   они уже есть). Создастся **ваша личная копия**.
4. Склонируйте свой репозиторий:
   ```bash
   git clone https://github.com/<ваш логин>/diary-blog.git
   cd diary-blog
   ```
5. Откройте шаблон `lab-01-git/my-project-readme.md`, заполните поля и добавьте блок «Студент»
   в начало файла `README.md` (в корне).
6. Выполните первый коммит:
   ```bash
   git status          # посмотрите, что изменилось
   git add .
   git commit -m "[lab-01] Репозиторий создан, README оформлен"
   git push
   ```
7. Проверьте историю и поставьте тег:
   ```bash
   git log --oneline
   git tag lab-01
   git push --tags
   ```
8. Убедитесь онлайн: `https://github.com/<ваш логин>/diary-blog/tree/lab-01` — открывается
   состояние на момент сдачи лабы.

## Самопроверка

- Что делает `git status` и зачем он нужен перед коммитом?
- Чем `git clone` отличается от `git init`?
- Зачем нужны теги? Что вы увидите, выполнив `git checkout lab-01`?
- Что будет, если сделать `git commit` без предварительного `git add`?
- Где хранится ваша «папка» проекта — на компьютере или на GitHub? (Ответ: и там, и там; локальная и удалённая копии. `push` синхронизирует их.)

- У вас есть личный репозиторий `diary-blog`, созданный из шаблона.
- В корневом README указан блок «Студент» с вашими данными.

- Вы свободно объясняете цикл add/commit/push и назначение тегов.

## Как отправить (протокол сдачи курса)

После каждой лабораторной отправляйте **одну строку** преподавателю:

```
Сдаю: lab-01
https://github.com/<ваш логин>/diary-blog/tree/lab-01
```

Важно: работайте **внутри папки своей лабораторной** (`lab-02/…`, `lab-05/…`), не трогайте
папки других лаб — тогда ничто не перемешается между заданиями.
