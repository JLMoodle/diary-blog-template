# Блог-дневник «Мой дневник»

Учебный проект курса веб-разработки. **15 лабораторных работ**, каждая из которых
развивает один и тот же проект: от простой HTML-страницы до полноценного
веб-приложения на PHP + MySQL (CRUD, оптимизация, защита).

Группа работает в **одном общем репозитории**: в каждой папке `lab-NN/`
студенты создают свою подпапку `<Фамилия>/` и ведут код в ней. Подробные
правила совместной работы — в разделе «Протокол группы» ниже.

---

## 1. Как начать (студенту)

1. Склонируйте **общий репозиторий группы**:

```bash
git clone https://github.com/JLMoodle/diary-blog-template.git
cd diary-blog-template
git config user.name  "Ваше Имя"
git config user.email "you@example.com"
```

2. В каждой лабе создайте свою подпапку по фамилии (латиницей) и работайте **только в ней**:

```bash
mkdir lab-02-html/<Фамилия>
# например: mkdir lab-02-html/ivanov
```

3. Скопируйте скелет лабы **целой папкой** в свою подпапку (сохранит css/js/data-пути), правите только своё, затем сдаёте:

```bash
git add lab-02-html/<Фамилия>/
git commit -m "[lab-02] <Фамилия>: семантическая структура страниц"
git pull --rebase
git push
```

**Сдача лабы = наличие вашей подпапки `<Фамилия>/` в main** общего репо.
Тег `v1.2` — актуальная версия шаблона (её ставит преподаватель, не студенты,
и обновляет, когда выходит новая редакция курса).

> Если при `git push` возникла ошибка `rejected` — это нормально для общего
> репозитория. Как разрулить конфликты и merge-коммиты: см. [`git-conflicts.md`](git-conflicts.md).

## 2. Курс одной схемой

| Лаб | Тема | Что появляется в проекте |
|-----|------|--------------------------|
| 01 | Git и GitHub | репозиторий, README, git-процесс |
| 02 | HTML | семантическая структура: header/nav/main/aside/footer |
| 03 | CSS | оформление, адаптивность, CSS-переменные |
| 04 | JavaScript: данные и функции | массив записей, `renderPosts`, сортировка/фильтр |
| 05 | JS DOM, формы, события | динамический интерфейс, форма + валидация, localStorage |
| 06 | Fetch API | записи грузятся из `data/posts.json` асинхронно |
| 07 | PHP (серверная часть) | `index.php`, части `includes/`, массив записей на PHP |
| 08 | PHP GET/POST | обработка форм (POST), поиск/фильтр (GET), валидация |
| 09 | PHP + MySQL | подключение БД (PDO), записи из таблицы `posts` |
| 10 | MySQL: таблицы, связи, ключи | схемы `users/categories/posts/comments`, ограничения, индексы |
| 11 | CRUD | добавление, просмотр, редактирование, удаление записей |
| 12 | Оптимизация SQL и PHP | JOIN, индексы, пагинация, prepared statements |
| 13 | Оптимизация JavaScript | делегирование, debounce, defer, минимизация DOM |
| 14 | Защита приложения | XSS, SQL-инъекции, CSRF, `password_hash`, секреты в `.env` |
| 15 | Комплексная финализация | тестирование, рефакторинг, документация, обновление тега `v1.2` |

## 3. Структура репозитория

```
diary-blog/
├── README.md               # этот файл: инструкция и отчёт (оформляется каждую лабу)
├── .gitignore              # исключает .env, логи, системные файлы
├── .env.example            # шаблон секретов БД (копируется в .env, лабы 9 и 14)
├── database/
│   └── schema.sql          # полная схема БД (изучается в лабах 9–10)
├── data/
│   └── posts.json          # «имитация API» для лабы 6 (уйдёт в лабе 9)
├── includes/               # PHP-части (с лабы 7)
│   ├── header.php
│   ├── footer.php
│   ├── functions.php
│   └── db.php              # PDO-подключение (с лабы 9)
├── css/
│   └── style.css           # оформление (лабы 3 и 13)
├── js/
│   └── main.js             # клиентские сценарии (лабы 4–6, 13)
├── index.html              # стартовая страница; в лабе 7 станет index.php
├── about.html              # страница «О блоге» (лаба 2)
├── posts/                  # PHP-страницы записей (лабы 7–11)
│   ├── index.php
│   ├── add.php
│   ├── edit.php
│   └── delete.php
└── tasks/                  # методички-задания по каждой лабе
    ├── 01-git.md  …  15-final.md
```

## 4. Как запускать (по мере роста проекта)

**Лабы 2–6 (клиентская часть):** достаточно открыть `index.html` в браузере.
Для `fetch()` (`data/posts.json`) нужен локальный веб-сервер.

**С лабы 7 (PHP):** встроенный сервер PHP, корень — папка конкретной лабы, чтобы
работали пути `/css/style.css`, `/posts/...`, `/users/...`:

```bash
php -S localhost:8000 -t lab-07-php
# откройте http://localhost:8000/index.php
```

В каждой следующей лабе подставляйте её папку (`-t lab-14-security`).

> Если запустить `php -S localhost:8000` из корня репозитория, страницы откроются,
> но стили/навигация будут ссылаться не на те пути.

**С лабы 9 (MySQL):**

```bash
mysql -u root -p < database/schema.sql   # создать БД и таблицы
cp .env.example .env                     # впишите свои доступы
```

## 5. Чек-лист защиты (финал, лаба 15)

- [ ] Git-история: коммит или тег по каждой лабораторной (`git log`, `git tag`)
- [ ] README оформлен: описание, схема БД, список функций, инструкция запуска
- [ ] Адаптивная вёрстка: корректно смотрится на телефоне и на десктопе
- [ ] Данные хранятся в MySQL, вывод через prepared statements
- [ ] Работает полный CRUD для записей (создать/читать/изменить/удалить)
- [ ] Есть поиск и фильтрация по категориям
- [ ] Формы валидируются и на клиенте, и на сервере
- [ ] Вывод экранирован (`htmlspecialchars`), SQL-инъекции невозможны
- [ ] Секреты не в коде: доступы БД только в `.env`
- [ ] Проект запускается на чистой машине по инструкции из README (3 команды)

## 6. Как сделать проект «своим»

- Имя автора, «О себе» и подписи — ваши реальные данные
- Своя цветовая тема через CSS-переменные в `css/style.css`
- Собственный набор записей и категорий (контент, интересный вам)
- Уникальные решения: теги, «избранное», комментарии — за рамками базовой схемы
